The owner-scoped reserve/bind endpoints default disabled via odk.protected-attempts.enabled=false; tests enable them explicitly on H2 and PostgreSQL. Only READY FOLLOW_UP is admitted. No new API returns permission to replay a completed or uncertain old unbound attempt. Existing duplicate conflict retained. ## Attachment durability candidate (V9, opt-in)

Legacy local storage now cleans partial input/checked-I/O failures and registers rollback cleanup before copying. The optional `odk.attachment-journal.enabled=true` path uses a database-generated namespace and 32 stable transaction-scoped coordination buckets. Before opening the uniquely named payload it creates and forces an empty journal marker; payload and parent directory are forced before metadata acceptance. Transaction completion removes only its marker (commit) or its own payload and marker (rollback); unknown completion retains the marker. Recovery uses an independent READ_COMMITTED transaction with the same bucket lock, reconciles the exact storage path with database metadata, verifies committed size/hash, and never scans or deletes legacy/unmarked or other-database files. It refuses symlink/invalid paths and retains uncertain/corrupt entries. `odk.attachment-journal.recovery-enabled=true` independently enables bounded scheduled passes; default false for both flags. Requires trusted private canonical POSIX local storage, no mixed database restore against live storage, no uncoordinated writers reusing managed names; verify actual filesystem fsync semantics, crash injection, and operational reconciliation of persistent markers before deployment. New locks affect only opted-in attachment writers; multi-attachment writes for a submission share one bucket. No web/S3 media writer changes. Existing real HTTP H2 and PostgreSQL tests opt in. Active-project authorization is rechecked before accepted-attempt evidence. Qualification pending.
