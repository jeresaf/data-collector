## Contract and implementation sequencing

The first implementation commit adds a bounded V1 canonical content commitment over actual multipart bytes and server-verified identity fields. Its digest is **not** a permission, receipt, or proof of absence. Existing Android package digest is intentionally distinct; it binds local generation and vault details. Android must implement the same wire commitment only once it has an authenticated server-issued attempt identity and actor binding. The wire profile admits current canonical XML and JPEG/PNG attachments only; media MIME sniffing, XML parsing and actual reference ownership remain required at intake, separate from hashing. No change to legacy OpenRosa, database migrations or runtime routing in this first commit.

Next commit(s) in this same branch: transactionally serialize admission with work lock and durable attempt identity, preserving source lock order for amendments; decide admission and replay semantics with a dedicated API that cannot be bypassed by unbound legacy linked writes for reserved work. ## Durable attempt admission candidate

V8 adds one immutable attempt per work, with server-issued UUID and unique form/instance fence. The owner-scoped reserve/bind endpoints default disabled via odk.protected-attempts.enabled=false; tests enable them explicitly on H2 and PostgreSQL. Only READY FOLLOW_UP is admitted. The request must supply the bound attempt UUID and actual multipart commitment; accepted submission ID is recorded in the same transaction as work completion. All OpenRosa intake now takes a form row lock before duplicate lookup, then the existing amendment source lock (where applicable), then work lock; the form lock is intentionally conservative and also protects reservations when the feature is disabled. This serializes intake for a form; throughput and interactions with non-OpenRosa writers remain to be qualified before enabling. No new API returns permission to replay a completed or uncertain old unbound attempt. Existing duplicate conflict retained. Test exercises reservation/bind idempotency, mutation, unlinked and unbound denial, competing exact HTTP requests and atomic acceptance. Additional rollback, authorization races, non-OpenRosa bypass, media sniff/reference validation, completed replay, Android consumer and amendment support remain open. No production migration or activation.
